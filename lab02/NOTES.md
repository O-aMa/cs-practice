Рабочая папка (рабочая директория) в контексте GitHub — это обычная папка на вашем компьютере, где вы напрямую работаете с файлами проекта.
 когда в контексте GitHub (и Git в целом) говорят «индекс», имеют в виду специальную промежуточную зону
 Коммит в GitHub — это зафиксированное сохранение состояния проекта в определённый момент времени. Проще говоря, это «снимок» всех изменённых, добавленных или удалённых файлов в репозитории.
 Git — это программа, которая работает на вашем компьютере. Она отслеживает изменения в коде, сохраняет историю правок и позволяет откатываться к предыдущим версиям проекта.

GitHub — это онлайн-сервис (платформа), где можно хранить Git-репозитории (папки с проектом и историей версий) в облаке. Он добавляет к возможностям Git инструменты для командной работы: возможность обсуждать код, создавать задачи (issues), предлагать изменения через pull request и автоматизировать процессы (например, запускать тесты при каждом коммите).
команда git diff в Git показывает различия между двумя состояниями репозитория: файлами в рабочей директории, индексом (staging area), коммитами, ветками или тегами. Она помогает увидеть, какие строки были добавлены, удалены или изменены. 
Основные варианты использования
Без аргументов git diff сравнивает рабочую директорию с индексом и показывает неиндексированные изменения — то, что вы изменили с момента последнего git add.
С опцией --staged (или --cached) git diff --staged сравнивает индекс с последним коммитом (HEAD) и показывает проиндексированные изменения — то, что будет закоммичено следующим.
